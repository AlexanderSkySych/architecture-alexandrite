# Мотивация

Кеширование необходимо для ускорения ответов сервиса и снижения нагрузки на бд. Часто повторяющиеся запросы статических или редко изменяющихся данных можно кешировать. 

Приорететные данные для кеширования:
- Информацию по готовым изделиям на продажу.
- Информация профиля пользователя.
- Информацию по выполненным заказам

# Предлагаемое решение

Добавить Redis-кеш по схеме Cache-Aside.
Если время позволит, можно добавить механизм refresh ahead для отдельных запросов.

# Стратегия инвалидации кешей
Изначально можно добавить кеширование на основе простого TTL, чтобы максимально быстро снизить нагрузку на бд. В первую очередь это следует сделать для истории заказов клиента, так как это статичные данные, которые не меняются.

Однако если время и ресурсы позволят, то можно добавить инвалидацию объектов кеша на основе изменений. Такое кеширование можно ввести для заказа, отправленного клиентом. После первичного создания объект заказа будут подвергаться минимальным изменениям, тем не менее клиент возможно будет часто его проверять. Если эти запросы не будут ходить в бд - это может ощутимо снизить нагрузку.

Такую же схему инвалидации можно добавить для данных профиля пользователя.
