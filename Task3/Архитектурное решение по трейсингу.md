# Мотивация

Трейсинг необходим для четкого понимания пути каждого запроса по системе. В случае просадок производительности или ошибки можно будет просмотреть полный путь интересуещего наз запроса и понять в каких конкретно местах и сколько конкретно времени провел интересующий нас запрос. Такая информация облегчит дебаггинг и подсветит наиболее медленные сегменты процесса.

Рекомендуемые метрики для сбора:
- Service-name - Ммя сервиса обрабатывающего запрос
- Request-id - Уникальный ID каждого запроса для сквозного отслеживания пути
- Request-url - Входной url запроса
- Request-data - Входные данные запроса
- Time-start - Время начала обработки запроса сервисом
- Time-end - Время окончания обработки запроса сервисом

# Предлагаемое решение

Приорететно трейсинг следует внедрить в компонент Shop API так как именно в нем находятся наиболее чувствительные взаимодействия с клиентами.

Затем следует добавить трейсинг в сервис MES API, так это вторая точка взаимодействия с клиентами. Также там содержатся тяжелые в плане производительности процессы, за которыми требуется особый мониторинг.

В последнюю очередь трейсинг следует добавлять CRM API, поскольку это малонагруженные сервисы для работы внутреннего персонала.

# Компромиссы
Приорететно нужно добавить метрики в те места, в которых это будет проще всего сделать, чтобы обеспечить сбор максимума информации за кратчайшие сроки.

# Аспекты безопасности

Собираемые данные рекомендуется собирать на внутреннем контуре на террритори компании чтобы повысить безопасность хранения данных.
